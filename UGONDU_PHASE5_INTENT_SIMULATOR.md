# Ugondu - Intent Simulator (Phase 5) Implementation

## Execution Context
In alignment with the goal of projecting abstract semantic intentions onto physical deterministic topologies, the `IntentSimulator` (`server/engine-core/src/intent/simulation/simulator.ts`) has been heavily refactored.

## Remediation Details

### 1. Deterministic Execution DAG Synthesis
The `IntentSimulator.simulate` method now fully converts a `DecomposedIntent` object into an `ArchitectureIR` payload, eliminating generic placeholders. 
- All nodes (`NETWORK`, `COMPUTE`, `DATABASE`) generated by the simulator now adhere strictly to the fabric engine's `NodeKind` format.
- Node IDs are now generated deterministically based on `workspaceId` prefixing (`ug-<hash>`), ensuring reproducible architecture diffs during successive deployments.

### 2. Comprehensive Requirement Mapping
Instead of dropping parsed intentions, the `IntentSimulator` now projects them onto the `ProvisioningNode` configurations:
- **Application Requirements**: Dynamically projects `intent.application.runtime` and `intent.application.port` onto the compute configuration. Build workloads and stateless workloads are accurately flagged.
- **Operational Requirements**: Analyzes `intent.operational.scaling` to boost the generic topology (scaling up `cpuCores` and `memoryMb`). Projects `intent.operational.backup` into database `backupRetentionDays`, and forwards auto-recovery intents to the runtime layer.
- **Security Requirements**: Maps `intent.security.leastPrivilege` into intrusion detection logic, forces private isolation modes for DB networks, and sets `secretsInjected` flags securely.
- **Availability Requirements**: Explicitly assigns `healthCheckEnabled`, `multiZoneRedundancy`, and strictly translates the `restartPolicy` mapping.

### 3. Early UPPIE Policy Gating (Shift-Left)
To prevent generating invalid topologies, the simulator now executes early "Shift-Left" compliance boundary validation. 
- If `enforceStrictIsolation` is required but the `targetCapabilities` of the provider do not support `VPC_PEERING`, the simulator rejects the intent immediately with `messages.error.intent_simulation_rejected` rather than waiting for the provisioning engine to fail.
- It performs equivalent boundary checks for `AUTO_SCALING` and `MULTI_ZONE` requirements.

### Summary
The Engine Core is now capable of performing true "Intent Architecture". It deterministically maps high-level abstract human-readable goals into a strictly structured Infrastructure Representation (`ArchitectureIR`), validating compliance boundaries along the way.
